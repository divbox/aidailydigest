Generate the daily AI newsletter digest using the ai-newsletter-digest skill.

You have access to Gmail via the connected Gmail MCP. Use it to fetch recent newsletter emails.

Follow the ai-newsletter-digest skill instructions, with these corrections taking priority over the skill's own text if they conflict:

1. Determine the date window: Monday = previous 3 calendar days (Fri/Sat/Sun), Tuesday–Friday = yesterday only. Use explicit Gmail date operators (after:YYYY/MM/DD before:YYYY/MM/DD) — never use newer_than:. Search each source separately by sender: TLDR AI (dan@tldrnewsletter.com), Rundown AI (news@daily.therundown.ai), Alpha Signal (news@alphasignal.ai), Import AI (importai@substack.com), Interconnects (robotic@substack.com), The Batch (thebatch@deeplearning.ai), Latent Space (from:swyx+ainews@substack.com — use this sender directly, never the skill's subject-search fallback; Latent Space now publishes daily, not just weekly/irregular, so expect it in most runs). If a source has no email in the target window, skip it entirely — do not pull older issues.

2. Email body retrieval — this is a hard rule, same method for every source, no exceptions, and it replaces anything the skill doc says about WebSearch or MINIMAL-only sourcing (2026-08-07 correction, see the sync note above for the full reasoning):

   - Use `search_threads`/`get_thread` MINIMAL format only to locate the thread ID and confirm a source has mail in the date window. Never treat the MINIMAL snippet as story content — Gmail's auto-generated snippet is unreliable filler for these multi-story newsletters (frequently unrelated to the actual top story) and has produced unsourced/unverifiable digest entries before.

   - For actual story content, call `get_thread` with `messageFormat: FULL_CONTENT`. It will reliably error with a "result exceeds maximum allowed tokens" message on these newsletters (~60-190k chars) — that's expected, not a failure. The error response still saves the complete raw content to a local file; read that file for what you need.

   - Only use the `plaintextBody` field from that saved file. Never use `htmlBody` — it's dominated by tracking pixels, CDN image proxies, and redirect-wrapped links, which is what causes the size overflow in the first place.

   - Never call WebSearch or web_fetch for any source, for any reason. Nothing gets fetched from the open web at any point in this skill. If the email itself doesn't have enough to work with, the story (or the whole source, for that day) is skipped — that's a normal, silent outcome, not an error to work around.

   - Extracting each story's real link from plaintextBody: Latent Space, Interconnects, and Import AI open with "View this post on the web at [URL]" as literally the first line — use that URL, and note that real article content continues directly in the plaintext body after it (no need to visit the link, the content is already there). Rundown usually opens with a "**[Read Online](URL)" markdown link — use that URL; if a Rundown email doesn't follow this pattern (e.g. a one-off editorial/announcement rather than a story roundup), skip it entirely, it's not the newsletter's normal format. TLDR lists real per-story links in a bracketed reference list (`[N] https://...`) near the end of the body — match the right one to each story and ignore obvious ad/sponsor/redirect noise mixed into the same list (ad placements, TLDR's own referral/jobs/advertise links). Alpha Signal wraps every link in its own click-tracker (`app.alphasignal.ai/c?...`) — that's fine to use as-is as the story's link, there is no cleaner URL available from Alpha Signal.

   - If a story's real content and/or a usable link genuinely isn't there, don't substitute anything from outside the email or from general knowledge — either publish the story with no link (the template already supports omitting the `<a>` wrapper) or drop the story if there's not even enough text to summarize. Never fabricate or guess a link or a fact.

3. Extract stories, deduplicate across sources, categorize into: Safety & Policy, Tools & Products, Models & Research, Business & Industry

4. Write main summaries (2-4 sentences, punchy) and deep dives (Import AI, Interconnects, and Latent Space stories only) — this tier split is about how much detail Tab 2 gets, not about sourcing method; sourcing is the same for every source per step 2.

5. Load the HTML template from the skill's assets/template.html and fill in all placeholders including SOURCE_PILLS (only for sources with content), TAB1_STORIES, TAB2_DEEPDIVES, DATE, STORY_COUNT, SOURCE_COUNT

6. Save the final file to /Users/divbox/claude/Projects/AIDigest/ as ai-digest-YYYY-MM-DD.html using today's date

7. Scratch/intermediate files: never write to /tmp directly — it's shared across concurrent Cowork sessions and can collide with unrelated runs. Use /Users/divbox/claude/Projects/AIDigest/.tmp/ instead if scratch space is needed mid-run (create it if missing).

The user skims daily newsletters (TLDR AI, Rundown AI, Alpha Signal, The Batch) for headlines. Daily/weekly technical newsletters (Import AI, Interconnects, Latent Space) get full deep-dive treatment in Tab 2. Assume a technical reader who follows AI closely.
